## dsh 写锁超时孤儿锁排查与修复
- 现象：`dsh runPlugin` 报 `atomic-write: timed out waiting for the writer lock at C:\Users\sunjuntao\.dsh\profiles\web\package.json.lock`，2s 后超时。
- 根因：`@deepseek-ai/dsh-atomic-write` 的 `withFileLock` 用 `<文件>.lock`（wx 独占创建，内容为持有进程 PID）做跨进程写锁；竞争方**永不主动删锁**，孤儿锁只能由运维清理。前次带 debugger 的 dsh 进程被 kill（PID 19500）未释放锁。
- 修复：确认锁内 PID 已死亡后删除孤儿锁。顺带发现 `C:\Users\sunjuntao\.dsh\task-board\ledger-v2.lock`（JSON 格式 pid/token/startedAt，pid 13980 亦死）一并清理。
- 本机排障坑（Script 工具）：
  - bash 无 ls/cat/coreutils；PowerShell 内联 stdout 不被回显 → 一律 `Out-File` 落盘再 Read。
  - safe-delete shim 拦截 `Remove-Item`/`fs.rm`（`$env:CODEBUDDY_SAFE_DELETE_ENABLED=0` 对 PowerShell Remove-Item 仍可能中途拦截）→ 用 node `fs.unlinkSync` 逐个删除最稳。
  - PID 存活判定：`Get-Process -Id <pid>`（PowerShell）或 `tasklist /FI "PID eq <pid>"`（node）。

## dsh 插件"后台进程被占满"机制澄清
- `dsh-plugin-manager` 的 `PluginManager` 是 dsh host（`bin.js --profile web --port 8899`，本机常驻 PID 19164）内一个**常驻服务**，不是固定进程池。
- 插件 install/enable/remove 走 `execa` 拉起**短期 pnpm 子进程**，跑完即退，由内存 `packageOperations`/`installs` 集合跟踪、`finally` 清理；无上限池。
- 但每个变更操作都经 `withFileLock(profileDir/package.json, { waitMs: 12e4 })`，**等锁最长 120 秒**。孤儿锁存在时，多个操作会同时挂起最长 120s → UI 表现为"后台进程占满/卡死"。
- 本机实测：dsh host 是 desktop 主进程(33328) 的子进程；host 当前挂有 VS Code 调试 watchdog(33100)。调试中强杀 host/desktop（而非先 detach）会留孤儿锁，是"占满"复发主因。Electron 多进程外壳 + 调试 watchdog 堆积会造成"很多 node 进程"的观感，但非插件池满。
- 排查"占满"：`Get-CimInstance Win32_Process` 抓 PID/PPID/CommandLine，看是否有 pnpm 子进程堆积 + 锁是否被占（LOCK=free 即非锁问题）。

## dsh 插件界面「新版本更新提示」
- 需求：dsh 插件管理界面（DshManager.vue）在插件有新版本时显示更新提示与新版本号。
- 后端 `checkDshPluginUpdates`（`src/main/dsh.ts`）早已实现（npm latest vs git HEAD sha 比对），但**未接入 IPC 桥**。本次补齐链路：
  - `src/main/ipc.ts`：import `checkDshPluginUpdates` + 注册 `IPC.DshPluginUpdates` handler（通道常量 `DshPluginUpdates: 'dsh:plugin-updates'` 已存在但未接线）。
  - `src/preload/index.ts`：新增 `dshCheckUpdates: (profile?) => ipcRenderer.invoke(IPC.DshPluginUpdates, profile)`，`ContainerApi` 自动包含。
  - `src/renderer/src/components/DshManager.vue`：加载插件后 `void checkUpdates()` 拉取提示，按 name 建索引；版本单元格内 `updateAvailable` 时显示 `可更新 <latest>` 徽标（点击触发更新对话框），检查中显示「检查更新中…」，更新按钮在有更新时转 warning 色。
- 顺带修复 `isNewerVersion` 隐患：原实现未剥离 `^ ~ >= < = * v` 等范围运算符，导致 `^1.2.3` 主版本被解析为 0，**所有带 caret 范围的插件都会被误判为可更新**；已加 `clean()` 剥离前缀并对非数字版本返回 false。
- 验证：`tsc -p tsconfig.node.json` 与 `vue-tsc -p tsconfig.web.json` 均 0 错误。

## dsh 插件 git 依赖显示 tag 版本号
- 需求补充：git 依赖也要显示版本号（读取 tag），而非只显示远端 HEAD 短 sha。
- 改动 `src/main/dsh.ts`：
  - `parseGitSpec` 改为捕获 `#` 后的原始 ref 与 `isSha` 标志（不再只认 hex sha；tag 形式如 `#v1.2.3` 也能识别）。
  - 新增 `latestGitTag(repo)`：`git ls-remote --tags` 解析 `refs/tags/*` 与 `^{}` 解引用行，取最高 semver tag 及其 commit sha（annotated tag 用 deref 行 sha）。
  - `checkDshPluginUpdates` git 分支：有 tag 时 `latest` 设为 tag 版本号，`updateAvailable` 按「pinned sha ≠ tag commit sha / pinned tag semver < latest tag」判定；无 tag 的仓库回退原 HEAD-sha 短 sha 逻辑。
  - 修正自身手误：`split(/\r?\n)` 漏写闭合 `/`，已补。
- UI 无需改动：`DshManager.vue` 的「可更新 {{ latest }}」直接渲染 tag 版本号。
