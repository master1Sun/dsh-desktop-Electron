## dsh 写锁超时孤儿锁排查与修复
- 现象：`dsh runPlugin` 报 `atomic-write: timed out waiting for the writer lock at C:\Users\sunjuntao\.dsh\profiles\web\package.json.lock`，2s 后超时。
- 根因：`@deepseek-ai/dsh-atomic-write` 的 `withFileLock` 用 `<文件>.lock`（wx 独占创建，内容为持有进程 PID）做跨进程写锁；竞争方**永不主动删锁**，孤儿锁只能由运维清理。前次带 debugger 的 dsh 进程被 kill（PID 19500）未释放锁。
- 修复：确认锁内 PID 已死亡后删除孤儿锁。顺带发现 `C:\Users\sunjuntao\.dsh\task-board\ledger-v2.lock`（JSON 格式 pid/token/startedAt，pid 13980 亦死）一并清理。
- 本机排障坑（Script 工具）：
  - bash 无 ls/cat/coreutils；PowerShell 内联 stdout 不被回显 → 一律 `Out-File` 落盘再 Read。
  - safe-delete shim 拦截 `Remove-Item`/`fs.rm`（`$env:CODEBUDDY_SAFE_DELETE_ENABLED=0` 对 PowerShell Remove-Item 仍可能中途拦截）→ 用 node `fs.unlinkSync` 逐个删除最稳。
  - PID 存活判定：`Get-Process -Id <pid>`（PowerShell）或 `tasklist /FI "PID eq <pid>"`（node）。

## dsh 插件"后台进程被占满"机制澄清
- `dsh-plugin-manager` 的 `PluginManager` 是 dsh host（`bin.js --profile web --port 8899`，本机常驻 PID 19164）内一个**常驻服务**，不是固定进程池。
- 插件 install/enable/remove 走 `execa` 拉起**短期 pnpm 子进程**，跑完即退，由内存 `packageOperations`/`installs` 集合跟踪、`finally` 清理；无上限池。
- 但每个变更操作都经 `withFileLock(profileDir/package.json, { waitMs: 12e4 })`，**等锁最长 120 秒**。孤儿锁存在时，多个操作会同时挂起最长 120s → UI 表现为"后台进程占满/卡死"。
- 本机实测：dsh host 是 desktop 主进程(33328) 的子进程；host 当前挂有 VS Code 调试 watchdog(33100)。调试中强杀 host/desktop（而非先 detach）会留孤儿锁，是"占满"复发主因。Electron 多进程外壳 + 调试 watchdog 堆积会造成"很多 node 进程"的观感，但非插件池满。
- 排查"占满"：`Get-CimInstance Win32_Process` 抓 PID/PPID/CommandLine，看是否有 pnpm 子进程堆积 + 锁是否被占（LOCK=free 即非锁问题）。

## 打包内置三大运行时（codex / openclaw / dsh）+ Windows 安装包
- 目标：安装包内自带 codex / openclaw / dsh，程序启动即运行；页面元数据把 dsh 插件市场也带上。用户拍板：**只打 Windows**、**codex 预装进 resources/codex**。
- 新增 `scripts/setup-codex.mjs`（镜像 setup-dsh/setup-openclaw）：用内置 node+npm 以 `npm install -g --prefix resources/codex @openai/codex@latest --ignore-scripts` 预装；`@openai/codex` 的平台二进制走 optionalDependencies（`@openai/codex-win32-x64` 内 vendor/codex.exe 约 307MB），无需 postinstall，`--ignore-scripts` 安全。
- **关键坑（npm 全局 prefix 布局）**：`npm i -g --prefix <dir>` 的 bin shim 不在 `node_modules/.bin`——Windows 直接落在 prefix 根（`codex.cmd`/`codex.ps1`/`codex`），POSIX 在 `<prefix>/bin`。provision 完成判定与 PATH 注入都必须按平台查对应路径，否则判"未装"+PATH 漏注入。
- `electron-builder.yml`：`extraResources` 增加 `resources/codex → codex`、`pages → pages`；`files` 增加 `!resources/**`、`!tools/**`，并从 `asarUnpack` 移除 `resources/**`。
  - **重要收益**：原先 `resources/**` 既被打进 app.asar（519.7MB）又被 extraResources 拷一遍、还被 asarUnpack 再解一遍，`dist/win-unpacked/resources` 高达 1117MB，安装包白白膨胀。打包器运行时的资源解析全部走 `process.resourcesPath`，`app.getAppPath()/resources/...` 只是 dev 兜底，所以排除 asar 打包是安全的。
- 启动即运行三件套：
  - `store.ts` DEFAULTS `autoStartPages: ['codex','openclaw','dsh-web']`（仅影响新装/未持久化设置的实例）。
  - `pages.ts` `autoStart()` 跳过 `kind==='terminal'` 的页（避免走 start() 报"不能在终端运行"）。
  - `openclaw.ts` 新增 `ensureBuiltinPages()`：仅 `app.isPackaged` 时把 `resources/pages` 下的 codex / dsh-web / dsh-plugin-market 首启 seed 到 userData/pages（可写、可随更新保留）；`index.ts` 启动流程调用。
  - **渲染层纠正**：terminal 类页面只有 `CliTerminalView`（`activeTerminalPage` 为真时才挂载）会真正执行 startCommand，`terminalStore.start()` 只开一个空 shell。因此 App.vue 改为在 `onMounted` 里把最后一个 terminal 类 autoStart 页设为 `activePageId`（不再误用 `openTerminal`）。
- `pty.ts` 新增 `codexBinDirs()` 注入 `resources/codex`（含 dev 回退候选），`terminalEnv()` 里排在 bundled node/pnpm 之后。
- **node-pty 实测（Windows/winpty）**：`pty.spawn('codex', …)` 不做 PATHEXT 解析 → `CreateProcess failed`；spawn 解析后的**完整 `.cmd` 路径可以正常拉起**（winpty 会经 cmd.exe）。所以 `whichOnPath()` 的 PATHEXT 解析是必需的，不能退回裸命令。
- 构建驱动（本机 npm 被沙箱拦成 wsl.exe，一律绕开 npm）：`node node_modules/typescript/bin/tsc` / `vue-tsc`、`node node_modules/electron-vite/bin/electron-vite.js build`、`node node_modules/electron-builder/cli.js --win --x64 --publish never --config.electronDist=<abs node_modules/electron/dist>`（后者跳过 Electron 下载）。打包前先 `cmd /c rmdir /s /q dist`（Node fs.rm 在大目录上会挂死）。
- 验证：`tsc -p tsconfig.node.json` 与 `vue-tsc -p tsconfig.web.json` 均 0 错误；`resources/codex/codex.cmd --version` → `codex-cli 0.155.1`（PATH 用内置 node）。

### 首轮打包出的坑（已修，务必记住）
1. **extraResources 会丢弃拷贝源的根 `node_modules`**。`app-builder-lib/out/util/filter.js` 的 `createFilter()` 开头就是
   `if (relative === "node_modules") return false`。原写法 `from: resources/dsh, to: dsh` 的相对路径正好是 `node_modules` → 整个目录被跳过，包里只剩 4 个 shim 文件，运行时必然找不到 CLI。
   **修法**：`from: resources, to: .`（相对路径变成 `dsh/node_modules`，保留）。已用 `tools/check-extraresources-filter.cjs`（复刻 createFilter + 项目自带 minimatch）实测：旧写法 `node_modules` → DROP，新写法全 KEEP。
   判别特征：`dist/win-unpacked/resources/<runtime>` 只有 4 个文件 / 0.0MB 就是复发了。
2. **同一棵树被塞三份**。`resources/**` 未从 `files` 排除时，既进 app.asar、又被 asarUnpack 解开、又被 extraResources 拷一遍，`resources/` 累计 1117MB。加 `!resources/**` 并从 asarUnpack 移除即可（运行时一律走 `process.resourcesPath`）。
3. **自带运行时不该同时声明为 dependencies**。`openclaw`(208MB) 与 `@deepseek-ai/dsh`(363MB) 之前列在 `dependencies`，而容器跑的是 `resources/` 里的 provisioned 副本、`src/` 从不 import 它们 → electron-builder 把项目 `node_modules` 那两份连同传递依赖一起打进 app.asar。改为 `devDependencies` 后 **app.asar 从 520MB 降到 56.3MB**、app.asar.unpacked 从 417.8MB 降到 9.3MB。
